ScopeOut: Guided Deal Scoping

Scoping a software deal usually means applying packaging rules from memory or a spreadsheet. ScopeOut turns those rules into a guided flow: a rep answers discovery questions and gets a validated scope, the reasons behind it, and a record ready for the CRM. It runs on the same rules engine as my chimney planner.

  • Rules engine
  • Catalog-driven
  • Approval workflow
  • Vercel serverless
  • Vanilla JS
Open ScopeOut

How it works

  • Each product is one catalog file: its questions, plans, rules and outputs. Import a new file and the whole tool reconfigures, with no code changes.
  • Rules can only raise the requirement, so the strictest one sets the plan, and every decision is shown with its reason.
  • RevOps edits packaging, price books, discount limits and simple rules in a draft, then publishes to every rep at once, with a change log.
  • Discounts above a rep’s limit need a sales manager’s approval, and buyers never see one that hasn’t been approved.
  • Buyers get a branded email summary, sent by a small serverless function protected by a CAPTCHA and rate limits.

What to try

  • Load an example scenario and watch the plan and the allocation squares change as you edit answers.
  • Switch to Buyer to see the self-serve versions for executives and project leads.
  • On the Admin tab, choose the RevOps admin role, change a rule, and publish it.
  • Use the Catalog menu to switch to a second, completely different product.
  • The demo ships with two catalogs: one modeled on a data-integration vendor’s public packaging, and a fictional analytics product. All prices are illustrative.
