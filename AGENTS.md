# davidcreason.com: instructions for AI coding agents

David Creason's personal portfolio site. Plain static HTML/CSS/JS, served by GitHub Pages from the `main`
branch of `project-creason/my_website` at `https://www.davidcreason.com` (the `www` address is canonical).
Pushing to `main` publishes the site within a few minutes. There is no staging site, so check your work before pushing.

## The one rule that matters most: `build.py` generates the site

Almost every page is generated by `python3 build.py`. **Never hand-edit a generated file.** A hand edit appears
live, but the next build silently overwrites it. To change a generated page, change `build.py` (or the resume
PDF) and rebuild.

**Generated, so never edit directly:**

- `index.html`, the homepage
- `projects/index.html` and `projects/<slug>/index.html`, except `projects/buffalo-trace-tracker/` (see below)
- `resume/index.html` (rendered by `resume.py` from the resume PDF)
- `contact/index.html` and `404.html`
- `home/` and `data-viz/`: redirects from the old Google Sites addresses
- `assets/projects.txt` and `assets/resume.txt`: plain-text notes the Portfolio AI Assistant reads
- `sitemap.xml` and `robots.txt`

**Hand-maintained, so edit these directly:**

- `build.py`, `resume.py`, `resume_source.py`: the generator itself
- `assets/style.css`, `assets/chat.js`, `assets/contact.js`, `assets/hero.js`, images under `assets/`
- `scopeout/`: the standalone ScopeOut demo app
- `projects/buffalo-trace-tracker/index.html`: a standalone page that `build.py` doesn't generate
- `scopeout-mailer/`: source for a Vercel function that sends ScopeOut emails (deployed by Vercel, not GitHub Pages)
- `assets/David_Creason_Resume.pdf`: replaced as a whole file (see "The resume")

## Workflow for every change

1. Install the one dependency if needed: `pip install pymupdf` (add `--break-system-packages` on managed Pythons).
2. Edit `build.py` (or a hand-maintained file).
3. Run `python3 build.py`. It must print `Checked: no phone numbers or email addresses in any page.` If it stops
   with an assertion, fix the cause; never remove or weaken the check.
4. Review `git diff`. Every changed file should be one you meant to change. Ignore `__pycache__/`.
5. Run `python3 build.py` a second time. It must produce **no further changes**. If it does, the build isn't
   deterministic or something was hand-edited; fix that before committing.
6. Commit `build.py` **together with** the regenerated files, then push to `main`.

encoding. Fix the encoding at the source; don't patch the output with HTML entities.

## How `build.py` is organized

- `PROFILE`: name, headline and current role (read from the resume PDF), plus the LinkedIn and GitHub links.
- `PROJECTS`: one dictionary per project. Order in the list is display order within each status group.
- `page(path, title, desc, section, body, extra_foot="", noindex=False)`: the shared template. It provides the
  header, navigation, footer, canonical link, social preview tags and GoatCounter analytics. Every page uses it.
  Don't write custom headers or footers into a page body.
- `detail_page(by["<slug>"], lede, sections_html)`: a project's case-study page. The lede is one paragraph; the
  sections are an HTML string.
- `tableau(div_id, "Workbook/View", alt)`: embeds a Tableau Public viz in the shared, styled frame.
- `NOTES_OVERRIDE`: hand-written assistant notes for projects whose pages are mostly interactive widgets.
- Near the end: the assistant notes, then the sitemap and robots.txt, then the final safety check.

### Adding a project

1. Add a dictionary to `PROJECTS`:

   ```python
   {
       "slug": "my-project",                 # URL: /projects/my-project/
       "title": "My Project",
       "status": "active",                   # "active" or "past"
       "badge": "Live",                      # short label on the card, e.g. "Live · in development", "Completed"
       "year": "2026",                       # or a range like "2018–2022"
       "summary": "One or two sentences. Used on the card, as the page description and in search results.",
       "tags": ["Python", "ETL"],
       "image": "/assets/projects/cards/my-project.jpg",
       "image_alt": "What the image shows",
       "links": [
           ("Read the case study", "/projects/my-project/", True),   # (label, href, primary button?)
           ("Source on GitHub", "https://github.com/project-creason/my-project", False),
       ],
   },
   ```

2. Put the card image in `assets/projects/cards/` (about 800×500) and larger screenshots in `assets/projects/`.
3. Add a `detail_page(by["my-project"], ...)` call next to the others. Reuse the existing classes:
   `cols` with `<section>` children for two columns, `ul.stats` for big numbers, `figure.shot-fig` with
   `img.hero-shot` for screenshots, `p.note`, `p.small`, `div.actions` with `a.btn` / `a.btn.ghost` for buttons.
   Read an existing `detail_page` call first and match its structure.
4. Build, review and push as above. The sitemap and the assistant's notes update automatically, and the assistant
   picks up the new notes within an hour.

**Standalone pages** (a hand-built page that doesn't use `detail_page`): give it a `<link rel="canonical">`, a meta
description and the same GoatCounter script as the template, and don't give it a `noindex` tag. Then add its path
to the `_urls` list in the sitemap block of `build.py`. If its text is mostly widgets, add a `NOTES_OVERRIDE` entry
so the assistant gets a clean description.

## The resume

`assets/David_Creason_Resume.pdf` is the source of truth for David's name, headline, current role, education, the
homepage key-numbers band and the whole `/resume/` page. To update it, replace the PDF, run the build and commit.
**Never upload the PDF through GitHub's website**, because that skips the build, and the build is what strips
contact details from the PDF. Don't hand-edit resume wording in `build.py` or `resume.py`.

## Content rules (always follow)

- **No phone number or email address anywhere**: not in pages, the PDF, `projects.txt` or `resume.txt`. The build
  strips them from the PDF and refuses to finish if one appears in a page. People reach David through the contact
  form (`/contact/`) or LinkedIn.
- **LinkedIn is `https://www.linkedin.com/in/dcreason/`.** Use `PROFILE["linkedin"]` rather than typing the URL.
- **ScopeOut** is presented as a standalone product. Don't say or imply it was built for an interview, a hiring
  exercise, a job application or any particular company. Quillmetrics is fictional and stays labeled as fictional.
- **Crestwood Home & Hearth** shows growth and margins as percentages and indexes only. Don't add dollar amounts,
  customer or invoice counts, or other absolute business figures.
- **Work done for an employer** (for example Property ETL Bench) is described only at the level its page already
  uses. Don't add internal system names, data, screenshots or business rules.
- Write about David's projects in the first person, as the existing pages do. Plain, specific language; no
  marketing filler.

## Search engines

The site is meant to be found in search. `page()` adds no robots tag by default.

- Use `noindex=True` only for pages that shouldn't appear in search (currently just the 404 page).
- Redirect pages from `redirect()` keep their `noindex` tag. Leave them as they are.
- Never add a sitewide `noindex`, and never block crawling in `robots.txt`.
- `sitemap.xml` and `robots.txt` are generated. Change them through `build.py`.

## Leave alone unless asked

- `CNAME` (custom domain) and `.nojekyll`
- `TURNSTILE_SITE_KEY` in `build.py`. It's the contact form's public bot-check key and is already on.
- Secrets. API keys for the contact form, the AI assistant and the ScopeOut mailer live in Vercel's environment
  variables, never in this repo.
- The old-address redirects in `home/` and `data-viz/`. They keep links from the old Google Sites site working.
